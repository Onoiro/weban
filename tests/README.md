# Тесты для Weban (Page Analyzer)

Этот документ описывает тестовую инфраструктуру проекта Weban.

## Структура тестов

```
tests/
├── conftest.py          # Общие фикстуры для тестов
├── test_app.py          # Тесты Flask приложения и маршрутов (упрощенные)
├── test_db.py           # Тесты функций работы с базой данных
├── test_parser.py       # Тесты парсера HTML и SEO данных
└── test_urls.py         # Тесты валидации и нормализации URL
```

## Установка зависимостей

Для запуска тестов необходимо установить dev-зависимости:

```bash
poetry install
```

## Запуск тестов

### Основные команды

```bash
# Запуск всех тестов
make test

# Запуск с подробным выводом
make test-verbose

# Запуск только unit тестов
make test-unit

# Запуск тестов с покрытием кода
make test-coverage

# Запуск только неудачных тестов (после первого запуска)
make test-failed

# Автоматический запуск при изменении файлов
make test-watch
```

### Прямые команды pytest

```bash
# Запуск всех тестов
poetry run pytest

# Запуск конкретного файла
poetry run pytest tests/test_urls.py

# Запуск с покрытием
poetry run pytest --cov=page_analyzer --cov-report=html

# Запуск с подробным выводом
poetry run pytest -v

# Остановка после первой ошибки
poetry run pytest -x

# Запуск только неудачных тестов
poetry run pytest --lf
```

## Что тестируется

### test_app.py
- Маршруты Flask приложения (статус коды)
- Обработка форм (валидация URL)
- Обработчики ошибок (404)
- Базовую структуру HTML ответов

**Примечание**: Тесты Flask упрощены из-за сложности мокирования функций БД.

### test_db.py
- Функции работы с базой данных
- Подключение к PostgreSQL
- CRUD операции
- Обработка ошибок подключения
- Мокирование psycopg2

### test_parser.py
- Парсинг HTML
- Извлечение SEO данных (title, h1, description)
- Обработка ошибок HTTP
- Валидация ответов
- Edge cases (пустые теги, некорректный HTML)

### test_urls.py
- Валидация URL
- Нормализация URL
- Проверка длины URL (255 символов)
- Edge cases для URL

## Фикстуры

### conftest.py
- `client` - Flask test client
- `mock_db_connection` - мок для базы данных
- `sample_url_data` - пример данных URL
- `sample_check_data` - пример данных проверки
- `mock_requests_response` - мок для HTTP ответа

## Покрытие кода

Для генерации отчета о покрытии кода:

```bash
make test-coverage
```

Отчет будет сохранен в папке `htmlcov/`. Откройте `htmlcov/index.html` в браузере для просмотра детального отчета.

## Настройки pytest

Конфигурация pytest находится в файле `pytest.ini`:

- `testpaths` - путь к папке с тестами
- `python_files` - маска для файлов тестов
- `addopts` - дополнительные опции по умолчанию
- `markers` - пользовательские маркеры

## Лучшие практики

1. **Изоляция тестов**: Каждый тест независим и не влияет на другие
2. **Мокирование**: Внешние зависимости (БД, HTTP) мокируются
3. **Читаемость**: Тесты имеют понятные названия и структуру
4. **Полнота**: Покрываются как успешные, так и ошибочные сценарии
5. **Производительность**: Тесты выполняются быстро (все ~2.5 секунды)
